## Вступление

Сказать:

> Эта лабораторная работа является продолжением 2.3. В 2.3 был написан
> предсказывающий LL(1)-анализатор языка описания грамматик с ручной таблицей.
> В 3.1 к нему добавлены семантический анализ дерева, вычисление FIRST и
> FOLLOW, автоматическое построение LL(1)-таблицы и вывод таблицы как
> Python-исходника. Затем генератор раскручивается на собственной грамматике.
> Для тестирования отдельно реализован калькулятор сложения и умножения.

## Демонстрация калькулятора

### 1. Показать грамматику

```bash
cat calculator/arithmetic_grammar.txt
```

Сказать:

> Это индивидуальный вариант. `E` задаёт сложение, `T` — умножение, `F` —
> числа и скобки. Такое разделение уровней задаёт приоритет умножения.

### 2. Сгенерировать таблицу

```bash
python3 generator.py calculator/arithmetic_grammar.txt generated/calc_table.py --mode string --sets
```

Сказать:

> Генератор разобрал описание, построил FIRST и FOLLOW, затем сформировал
> таблицу. Для калькулятора терминалы выводятся строками, поэтому используется
> `--mode string`.

Показать часть таблицы:

```bash
sed -n '1,120p' generated/calc_table.py
```

Сказать:

> Таблица представлена обычным литералом словаря Python с ключами-парами.
> JSON и сериализация не используются.

### 3. Запустить калькулятор

```bash
python3 -m calculator.calculator
```

Ввести:

```text
(2+3)*4
```

Ожидаемый результат:

```text
20
```

Сказать:

> Калькулятор является отдельной программой. Он импортирует сгенерированную
> таблицу, использует общий предсказывающий анализатор и вычисляет значение по
> построенному дереву.

## Демонстрация самоприменения

### 1. Показать грамматику генератора

```bash
cat generator_grammar.txt
```

Сказать:

> Это формальная грамматика входного языка генератора, записанная на самом
> входном языке. Она описывает конструкции правил, альтернатив, терминалов,
> нетерминалов, `epsilon` и аксиомы.

### 2. Первый шаг раскрутки

```bash
python3 generator.py generator_grammar.txt generated/generated_input_table.py \
  --mode enum --sets
```

Сказать:

> На первом шаге описание языка разбирается с ручной таблицей, оставшейся от
> лабораторной 2.3. Результат — автоматически построенная таблица входного
> языка генератора.

### 3. Второй шаг раскрутки

```bash
python3 generator.py generator_grammar.txt generated/generated_input_table_2.py \
  --mode enum --bootstrap-table generated/generated_input_table.py
```

Сказать:

> Теперь ручная таблица заменена на автоматически сгенерированную. Генератор
> снова получает собственную грамматику и строит таблицу повторно.

### 4. Сравнить результаты

```bash
cmp generated/generated_input_table.py generated/generated_input_table_2.py
echo $?
```

Ожидаемый результат:

```text
0
```

Сказать:

> Файлы совпадают байт-в-байт. Это показывает, что генератор самоприменим и
> после раскрутки даёт устойчивый результат.

Дополнительно можно запустить:

```bash
python3 tests/run_tests.py
```

Строка:

## Демонстрация ошибки LL(1)

Если преподаватель просит показать обработку ошибок:

```bash
printf '`axiom S `is "a" `or "a" "b" `end\n' > /tmp/not_ll1.txt
python3 generator.py /tmp/not_ll1.txt /tmp/not_ll1_table.py --mode string
echo $?
```

Ожидается сообщение о конфликте:

```text
Error: Grammar is not LL(1): conflict for 'S' with lookahead 'a' ...
1
```

Сказать:

> Обе продукции начинаются с терминала `"a"` и пытаются занять одну ячейку
> таблицы `(S, "a")`. Поэтому грамматика не является LL(1), генерация
> прерывается с кодом ошибки.

## Возможные вопросы и ответы

### Что такое предсказывающий анализ?

Это LL(1)-разбор. Для выбора продукции достаточно текущего нетерминала и
одного следующего токена. Продукция выбирается из таблицы по ключу
`(нетерминал, lookahead)`.

### Почему анализатор называется LL(1)?

Первое `L` означает чтение входа слева направо. Второе `L` означает построение
левого вывода. Число `1` означает использование одного следующего токена.

### Что было сделано в 2.3, а что добавлено в 3.1?

В 2.3 были лексер, ручная таблица, предсказывающий разбор и дерево. В 3.1
добавлены семантический анализ дерева, `FIRST`, `FOLLOW`, генерация таблицы,
вывод Python-исходника, самоприменение и отдельный калькулятор.

### Что такое FIRST?

`FIRST(alpha)` — множество терминалов, с которых могут начинаться цепочки,
выводимые из `alpha`. Если возможна пустая цепочка, в множество входит
`epsilon`.

### Что такое FOLLOW?

`FOLLOW(A)` — множество терминалов, которые могут находиться сразу после
нетерминала `A`. Для аксиомы добавляется маркер конца ввода `EOF`.

### Как по FIRST и FOLLOW строится таблица?

Для продукции `A -> alpha` она записывается в ячейки `(A, t)` для всех
терминалов `t` из `FIRST(alpha)`. Если `alpha` может быть пустой, продукция
также записывается в ячейки для терминалов из `FOLLOW(A)`.

### Как определяется, что грамматика не LL(1)?

Если разные продукции пытаются занять одну ячейку таблицы. Генератор сообщает
координаты конфликтующего правила и прекращает работу.

### Зачем нужен семантический анализ после построения дерева?

Дерево показывает синтаксическую структуру текста, но для вычисления `FIRST`,
`FOLLOW` и таблицы нужен удобный набор продукций. Семантический анализ
превращает дерево в `GrammarSpec` и проверяет корректность правил.

### Какие семантические ошибки проверяются?

Проверяются отсутствие аксиомы, несколько аксиом и ссылка на нетерминал без
правила. LL(1)-конфликт обнаруживается при построении таблицы. Проверка
объявлений символов не нужна, потому что в нашем варианте отдельных объявлений
нет.

### Почему не реализовано восстановление после ошибок?

По условию лабораторной работы восстановление не требуется. При первой ошибке
выводится сообщение с координатами, после чего генерация прекращается.

### Почему таблица выводится как Python-код?

По условию таблица должна быть составным литералом на языке реализации.
Лабораторная написана на Python, поэтому выводится файл с обычным словарём
`PARSE_TABLE`. Использование JSON запрещено.

### Что такое самоприменение?

Генератор получает описание собственного входного языка и создаёт таблицу для
собственного парсера. После этого сгенерированная таблица заменяет ручную, и
повторный запуск должен дать тот же результат.

### Почему для первого запуска всё равно нужна ручная таблица?

До первого запуска автоматически построенной таблицы ещё нет. Используется
ручная таблица из 2.3, после чего генератор создаёт её эквивалент
автоматически.

### Что доказывают две проверки равенства?

`Self-application table equality: True` означает, что повторная генерация с
автоматической таблицей даёт тот же файл. `Manual table equality: True`
означает, что автоматически построенная таблица эквивалентна ручной таблице
из 2.3.

### Один ли анализатор используется для генератора и калькулятора?

Да. Универсальный стековый алгоритм находится в `predictive_parser.py`.
Различаются лексеры, таблицы, аксиомы и семантическая обработка деревьев.

### Зачем нужны два режима вывода терминалов?

Лексер входного языка генератора возвращает элементы перечисления `TokenType`,
поэтому для него используется `--mode enum`. Лексер калькулятора возвращает
строковые типы токенов, поэтому для него используется `--mode string`.

### Почему калькулятор является отдельной программой?

Это прямое требование задания. Он демонстрирует применение сгенерированной
таблицы к рабочему языку, а не является частью генератора.

### Как в калькуляторе обеспечен приоритет умножения?

Грамматика разделена на уровни: `E` отвечает за сложение, `T` за умножение,
`F` за числа и скобки. Поэтому умножение вычисляется внутри `T` до сложения в
`E`.
