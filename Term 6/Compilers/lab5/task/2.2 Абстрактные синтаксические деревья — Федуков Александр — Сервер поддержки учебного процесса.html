1 Цель работы

Целью данной работы является получение навыков составления грамматик и проектирования синтаксических деревьев.

2 Исходные данные

В данной лабораторной работе требуется разработать синтаксический анализатор, который, принимая на входе текст на входном языке, строит для него абстрактное синтаксическое дерево.

Описание входного языка и пример программы на нём приводятся в индивидуальном варианте, по описанию следует построить лексическую структуру и грамматику данного языка.

Парсер следует писать на языке Python версии не ниже 3.10 с использованием библиотеки parser_edsl.py (скачать архив), которую также можно загрузить со страницы https://github.com/bmstu-iu9/parser_edsl_python.

Краткое руководство по использованию библиотеке и пример решения приведены ниже

2.1 Краткое руководство по библиотеке parser_edsl.py

Библиотека parser_edsl.py позволяет создавать парсеры (работающие по алгоритму LALR, LL(1) или Эрли) в наглядной форме: достаточно описать нетривиальные лексические домены с использованием регулярных выражений и грамматику в БНФ-подобной нотации.

В процессе разбора библиотека вычисляет атрибуты терминальных и нетерминальных символов:

  • функция, вычисляющая атрибут терминального символа, передаётся в конструктор терминального символа — её аргументом является лексема,
  • функция, вычисляющая атрибут нетерминального символа, записывается в правиле грамматики — её аргументами являются атрибуты символов правой части правила.

Результатом разбора является атрибут аксиомы.

Библиотека не умеет восстанавливаться при ошибках при лексическом и синтаксическом анализе: исключение выбрасывается на первой же ошибке.

Рассмотрим пример — напишем синтаксический анализатор для обычной грамматики арифметических выражений:

E → E + T | E - T | T
T → T * F | T / F | F
F → INTEGER | ( E )

Для примера напишем калькулятор, который принимает запись арифметического выражения и вычисляет его значение. Будем считать, что с терминальным символом INTEGER и каждым из трёх нетерминалов связан атрибут «число», соответственно, значение целого числа и значения выражения, слагаемого и сомножителя.

Подключаем библиотеку к программе:

import parser_edsl as pe

Описываем классы для нетерминальных символов:

Expr = pe.NonTerminal('Expr')
Term = pe.NonTerminal('Term')
Factor = pe.NonTerminal('Factor')

Имена, передаваемые в конструктор, используются только в отладочном выводе.

Лексическая структура языка содержит только знаки арифметических действий, скобки и целые числа. Знаки действий и скобки явным образом описывать как лексические домены не нужно — их можно непосредственно описать в грамматике строками. Явно следует описать только целое число:

INTEGER = pe.Terminal('INTEGER', '[0-9]+', int)

Здесь первый параметр конструктора — имя терминального символа, второй — регулярное выражение, третий — функция вычисления атрибута.

  • Имя терминального символа используется в отладочном выводе и при выдаче сообщений о синтаксических ошибках.
  • Регулярное выражение описывается в синтаксисе, используемой модулем re стандартной библиотеки Python’а.
  • В роли функции вычисления атрибута здесь используется конструктор целого числа int — он будет преобразовывать десятичную запись числа в целое.

Теперь мы можем описать грамматику:

Expr |= Expr, '+', Term, lambda x, y: x + y
Expr |= Expr, '-', Term, lambda x, y: x - y
Expr |= Term

Term |= Term, '*', Factor, lambda x, y: x * y
Term |= Term, '-', Factor, lambda x, y: x / y
Term |= Factor

Factor |= INTEGER
Factor |= '(', Expr, ')'

Правило грамматики записывается как

‹нетерминал› |= ‹символы через запятую›, ‹функция›

причём функцию в конце в некоторых случаях можно не писать. Разберём детальнее:

Expr |= Expr, '+', Term, lambda x, y: x + y

Здесь мы записали правило E → E + T. Терминальный символ + в правиле записан как строка — это допустимо для знаков операций и ключевых слов. Функция вычисления атрибута lambda x, y: x + y принимает два параметра, т.к. только два символа в правиле имеют атрибут (у терминальных символов, описанных строками, атрибута нет). Атрибутом символа Expr в левой части правила будет сумма атрибутов символов Expr и Term в правой части.

Если в правиле отсутствует функция вычисления атрибута, то в правой части правила должно быть не более одного символа, имеющего атрибут. Если символ с атрибутом есть, то он наследуется нетерминалом из левой части. Если атрибута нет ни у одного символа — нетерминал в левой части останется без атрибута.

В правилах

Expr |= Term
Term |= Factor
Factor |= INTEGER
Factor |= '(', Expr, ')'

функции вычисления атрибутов отсутствуют. В первых трёх из них в правой части всего один символ и он содержит атрибут. В последнем атрибуты у скобок отсутствуют, поэтому Factor из левой части получит атрибут от Expr из правой.

После того, как мы описали грамматику, можем построить парсер:

parser = pe.Parser(Expr, method=pe.EARLEY)

Конструктор парсера принимает аксиому грамматики. Символы (терминальные и нетерминальные), образующие язык, определяются как прямо или косвенно доступные из аксиомы.

Необязательный параметр method определяет метод разбора. Метод pe.EARLEY использует алгоритм Эрли, позволяющий разбирать произвольные грамматики.

Парсеру можно указать лексические домены, которые следует игнорировать — пробельные символы и комментарии. Укажем их:

parser.add_skipped_domain('\\s')        # пробельные символы
parser.add_skipped_domain('\\{.*?\\}')  # комментарии вида {...}

Теперь мы можем использовать пробелы в качестве разделителя и использовать комментарии вида { это комментарий }.

Синтаксический анализ запускается методом .parse(text):

>>> parser.parse('21 * (1 + { комментарий } 1)')
42

Давайте добавим в язык вещественные числа:

REAL = pe.Terminal('REAL', '[0-9]+(\\.[0-9]*)?(e[-+]?[0-9]+)?', float)

Регулярное выражение описывает обычный синтаксис для вещественных чисел: целая часть, за которой следуют дробная часть (начинается с точки) и порядок числа (начинается с e), причём и дробная часть, и порядок могут отсутствовать.

В лексической структуре конфликт — последовательность десятичных цифр может распознаваться и как целое, и как вещественное число. Будем считать, что у вещественного числа обязательно должна быть или дробная часть, или порядок (одновременно оба тоже можно).

Конфликт разрешается указанием приоритета. Приоритет лексических доменов, создаваемых при помощи Terminal, равен 5, приоритет доменов, описанных в грамматике строками — 10. Укажем, что приоритет целых чисел равен 7:

INTEGER = pe.Terminal('INTEGER', '[0-9]+', int, priority=7)

Добавим в грамматику вещественные числа:

Factor |= REAL

А теперь давайте расширим язык именованными константами:

import math

CONSTANTS = {
    'pi': math.pi,
    'e': math.e,
    'Na': 6.02214076e23, # Постоянная Больцмана
    'kB': 1.380649e-23,  # Число Авогадро
}

CONST = pe.Terminal('CONST', '[A-Za-z]+', str)

Атрибут константы — её имя, записаное в виде строки.

Добавим константы в грамматику:

Factor |= CONST, lambda name: CONSTANTS[name]

Добавим в грамматику операцию вычисления остатка от деления:

Term |= Term, 'mod', Factor, lambda x, y: x % y

Заметим, что строка mod принадлежит и домену констант (т.к. состоит из букв) и домену операции вычисления остатка. Конфликта нет, т.к. приоритет буквально заданного терминального символа равен 10, а приоритет символа, описанного конструктором Terminal — 5.

Сделаем ключевое слово mod нечувствительным к регистру:

import re

KW_MOD = pe.Terminal('mod', 'mod', lambda name: None,
                     re_flags=re.IGNORECASE, priority=10)

Term |= Term, KW_MOD, Factor, lambda x, y: x % y

Что здесь нового:

  • отсутствие атрибута выражается значением None,
  • использован необязательный параметр re_flags, задающий флаги компиляции регулярного выражения (по умолчанию — re.MULTILINE),
  • приоритет указан обычный для ключевых слов — 10.

Не всегда лексический домен возможно или удобно описывать при помощи регулярного выражения — атрибуты токенов могут ограничиваться семантикой языка. К примеру, добавим в рассмотренный пример ограничение: значения целочисленных литералов не могут превышать 65535. Описать такое ограничение при помощи регулярного выражения возможно, но крайне громоздко и сложно для сопровождения (можете поразвлекаться на досуге😉). Вместо этого можно разбирать произвольные последовательности десятичных цифр и проверять, что они соответствуют числам соответствующего диапазона — в противном случае сообщать об ошибке. Для этой цели в библиотеке предусмотрен специальный класс исключений TokenAttributeError. Пример его использования:

# Функция вычисления атрибута
def bounded_int(value):
    ivalue = int(value)
    if ivalue < 65536:
        return ivalue
    else:
        raise pe.TokenAttributeError(f'Слишком большое число: ' + value)

# …пропущено…

INTEGER = pe.Terminal('INTEGER', '[0-9]+', bounded_int, priority=7)

# …пропущено…

try:
    bad_expr = '7 + 100500'
    print('Пример лексической ошибки:', bad_expr)
    print(parser.parse(bad_expr))
except pe.Error as e:
    print('Ошибка:', e.pos, e.message)

Будет напечатано:

Пример лексической ошибки: 7 + 100500
Ошибка: (1, 5) Слишком большое число: 100500

В архиве этот пример тоже присутствует.

Алгоритм Эрли, который предлагается использовать в этой лабораторной работе, в общем случае способен разбирать и неоднозначные грамматики. Однако, в parser_edsl используется модифицированная версия алгоритма, которая при неоднозначном разборе сообщает об ошибке — это позволяет обнаруживать и отлаживать неоднозначности в грамматике. Рассмотрим пример:

import parser_edsl as pe


# Нетерминальные символы
Expr = pe.NonTerminal('Expr')

# Терминальные символы
INTEGER = pe.Terminal('INTEGER', '[0-9]+', int, priority=7)


# Правила грамматики
Expr |= Expr, '+', Expr, lambda x, y: x + y
Expr |= Expr, '-', Expr, lambda x, y: x - y
Expr |= INTEGER


# Парсер
parser = pe.Parser(Expr, method=pe.EARLEY)
parser.add_skipped_domain('\\s')        # пробельные символы

print(parser.parse('100 + 200'))
try:
    print(parser.parse('100 + 200 - 150'))
except pe.ParseError as e:
    print('Ошибка:', e)

Грамматика, очевидно, неоднозначная, и для выражения с неоднозначным разбором выводится сообщение об ошибке:

300
Ошибка: (1, 1) Неопределенная грамматика: найдено 2 путей разбора

2.2 Пример решения лабораторной работы

Рассмотрим грамматику подмножества Паскаля, дополненную правоассоциативной операцией возведения в степень **. В программе можно определять переменные типов integer, real и boolean, из операторов доступны оператор присваивания, ветвления (считаем, что ветка else обязательна), циклы while и for. Операторы можно группировать при помощи begin и end.

Традиционно в Паскале ключевые слова и идентификаторы нечувствительны к регистру.

Примечание. Необязательность ветки else заметно усложнит рассматриваемый пример.

В выражениях можно использовать арифметические операции +, -, *, /, div (целочисленное деление, аналог // в Python), mod (вычисление остатка от деления) и ** (новая операция возведения в степень), логические операции and, or, not, операции сравнения >, <, =, <>, >= и <=.

Приоритет операций по убыванию:

  1. not
  2. **, правоассоциативная
  3. *, /, div, mod, and
  4. +, -, or
  5. >, <, =, <>, >=, <= (неассоциативные)

В выражениях можно использовать круглые скобки. Перед первым слагаемым может располагаться необязательный знак + или -.

Пример программы:

var
  x: integer;
  y: real;
  b: boolean;
begin
  x := 100;
  y := 2.5;
  z := x > y;
  if z and (x / y > 7.0) then
    while x > y do
      x := x - y
  else
    x := x * y;
end

Сформулируем абстрактный синтаксис.

Программа начинается с объявления переменных, за которым располагается последовательность операторов:

Program → VAR VarDefs BEGIN Statements END

Объявления переменных — ноль и более объявлений переменных:

VarDefs → VarDef*

Объявление переменной состоит из имени и типа, разделённых знаком двоеточия:

VarDef → VARNAME : Type ;

Тип — целый, вещественный или логический:

Type → INTEGER | REAL | BOOLEAN

Последовательность операторов — ноль или более операторов, разделённых точкой с запятой:

Statements → Statement ; … ; Statement | ε

Оператор — присваивание, ветвление, цикл с предусловием, цикл со счётчиком, последовательность операторов в операторных скобках begin … end и пустой оператор, который ничего не делает:

Statement → VARNAME := Expr
          | IF Expr THEN Statement ELSE Statement
          | WHILE Expr DO Statement
          | FOR VARNAME := Expr TO Expr DO Statement
          | BEGIN Statements END
          | ε

Выражение — переменная, константа, двуместная операция, одноместная операция:

Expr → VARNAME
     | Const
     | Expr BinOp Expr
     | UnOp Expr
Const → INT_CONST | REAL_CONST | TRUE | FALSE
BinOp → + | - | * | / | ** | AND | OR | > | < | >= | <= | = | <> | DIV | MOD
UnOp → + | - | NOT

Перейдём к конкретной грамматике:

Program → VAR VarDefs BEGIN Statemens END
VarDefs → ε | VarDefs VarDef
VarDef → VARNAME : Type ;
Type → INTEGER | REAL | BOOLEAN

Statements → Statement | Statements ; Statement
Statement → VARNAME := Expr
          | IF Expr THEN Statement ELSE Statement
          | WHILE Expr DO Statement
          | FOR VARNAME := Expr TO Expr DO Statement
          | BEGIN Statements END
          | ε

Expr → ArithmExpr
     | ArithmExpr CmpOp ArithmExpr
CmpOp → > | < | >= | <= | = | <>

ArithmExpr → Term | + Term | - Term | ArithmExpr AddOp Term
AddOp → + | - | OR

Term → Factor | Term MulOp Factor
MulOp → * | / | DIV | MUL | AND

Factor → Power | Power ** Factor

Power → NOT Power | VARNAME | Const | ( Expr )

Const → INT_CONST | REAL_CONST | TRUE | FALSE

Для учёта приоритета операций пришлось ввести несколько вспомогательных токенов для выражений.

Узлы синтаксического дерева мы будем описывать при помощи классов данных (dataclasses) языка Python. Тип переменной опишем при помощи перечисления.

Каждый узел абстрактного синтаксического дерева будем сопровождать комментарием с соответствующими правилами абстрактного синтаксиса.

import abc
import enum
import typing
from dataclasses import dataclass


# Type → INTEGER | REAL | BOOLEAN
class Type(enum.Enum):
    Integer = 'INTEGER'
    Real = 'REAL'
    Boolean = 'BOOLEAN'


# VarDef → VARNAME : Type ;
@dataclass
class VarDef:
    name : str
    type : Type


class Statement(abc.ABC):
    pass


# Program → VAR VarDefs BEGIN Statements END
@dataclass
class Program:
    var_defs : list[VarDef]
    statements : list[Statement]


class Expr(abc.ABC):
    pass


# Statement → VARNAME := Expr
@dataclass
class AssignStatement(Statement):
    variable : str
    expr : Expr


# Statement → IF Expr THEN Statement ELSE Statement
@dataclass
class IfStatement(Statement):
    condition : Expr
    then_branch : Statement
    else_branch : Statement


# Statement → WHILE Expr DO Statement
@dataclass
class WhileStatement(Statement):
    condition : Expr
    body : Statement


# Statement → FOR VARNAME := Expr TO Expr DO Statement
@dataclass
class ForStatement(Statement):
    variable : str
    start : Expr
    end : Expr
    body : Statement


# Statement → BEGIN Statements END
@dataclass
class BlockStatement(Statement):
    body : list[Statement]


# Statement → ε
@dataclass
class EmptyStatement(Statement):
    pass


# Expr → VARNAME
@dataclass
class VariableExpr(Expr):
    varname : str


# Expr → Const
# Const → INT_CONST | REAL_CONST | TRUE | FALSE
@dataclass
class ConstExpr(Expr):
    value : typing.Any
    type : Type


# Expr → Expr BinOp Expr
# BinOp → + | - | * | / | ** | AND | OR | > | < | >= | <= | = | <> | DIV | MOD
@dataclass
class BinOpExpr(Expr):
    left : Expr
    op : str
    right : Expr


# Expr → UnOp Expr
# UnOp → + | - | NOT
@dataclass
class UnOpExpr(Expr):
    op : str
    expr : Expr

Классы данных (аннотация @dataclass) позволяют автоматически генерировать инициализатор (метод __init__), сравнение на равенство и человекочитаемое строковое представление (метод __repr__). Аннотации типов Python игнорирует, однако, их могут учитывать вспомогательные средства (линтеры, плагины IDE…).

Некоторые узлы дерева сопровождаются двумя правилами. Например, для узла двуместной операции указано как правило для Expr, так и правило для BinOp. Если бы мы выделили двуместную операцию в отдельный тип-перечисление, то комментарий для BinOp был бы перед перечислением.

Опишем теперь лексическую структуру и грамматику:

import parser_edsl as pe
import re


INTEGER = pe.Terminal('INTEGER', '[0-9]+', int, priority=7)
REAL = pe.Terminal('REAL', '[0-9]+(\\.[0-9]*)?(e[-+]?[0-9]+)?', float)
VARNAME = pe.Terminal('VARNAME', '[A-Za-z][A-Za-z0-9]*', str.upper)

def make_keyword(image):
    return pe.Terminal(image, image, lambda name: None,
                       re_flags=re.IGNORECASE, priority=10)

KW_VAR, KW_BEGIN, KW_END, KW_INTEGER, KW_REAL, KW_BOOLEAN = \
    map(make_keyword, 'var begin end integer real boolean'.split())

KW_IF, KW_THEN, KW_ELSE, KW_WHILE, KW_DO, KW_FOR, KW_TO = \
    map(make_keyword, 'if then else while do for to'.split())

KW_OR, KW_DIV, KW_MOD, KW_AND, KW_NOT, KW_TRUE, KW_FALSE = \
    map(make_keyword, 'or div mod and not true false'.split())


NProgram, NVarDefs, NVarDef, NType, NStatements = \
    map(pe.NonTerminal, 'Program VarDefs VarDef Type Statements'.split())

NStatement, NExpr, NCmpOp, NArithmExpr, NAddOp = \
    map(pe.NonTerminal, 'Statement Expr CmpOp ArithmOp AddOp'.split())

NTerm, NMulOp, NFactor, NPower, NConst = \
    map(pe.NonTerminal, 'Term MulOp Factor Power Const'.split())


NProgram |= KW_VAR, NVarDefs, KW_BEGIN, NStatements, KW_END, Program

NVarDefs |= lambda: []
NVarDefs |= NVarDefs, NVarDef, lambda vds, vd: vds + [vd]

NVarDef |= VARNAME, ':', NType, ';', VarDef

NType |= KW_INTEGER, lambda: Type.Integer
NType |= KW_REAL, lambda: Type.Real
NType |= KW_BOOLEAN, lambda: Type.Boolean

NStatements |= NStatement, lambda st: [st]
NStatements |= NStatements, ';', NStatement, lambda sts, st: sts + [st]

NStatement |= VARNAME, ':=', NExpr, AssignStatement
NStatement |= (
    KW_IF, NExpr, KW_THEN, NStatement, KW_ELSE, NStatement, IfStatement
)
NStatement |= KW_WHILE, NExpr, KW_DO, NStatement, WhileStatement
NStatement |= (
    KW_FOR, VARNAME, ':=', NExpr, KW_TO, NExpr, KW_DO, NStatement, ForStatement
)
NStatement |= KW_BEGIN, NStatements, KW_END, BlockStatement
NStatement |= EmptyStatement

NExpr |= NArithmExpr
NExpr |= NArithmExpr, NCmpOp, NArithmExpr, BinOpExpr

def make_op_lambda(op):
    return lambda: op

for op in ('>', '<', '>=', '<=', '=', '<>'):
    NCmpOp |= op, make_op_lambda(op)

NArithmExpr |= NTerm
NArithmExpr |= '+', NTerm, lambda t: UnOpExpr('+', t)
NArithmExpr |= '-', NTerm, lambda t: UnOpExpr('-', t)
NArithmExpr |= NArithmExpr, NAddOp, NTerm, BinOpExpr

NAddOp |= '+', lambda: '+'
NAddOp |= '-', lambda: '-'
NAddOp |= KW_OR, lambda: 'or'

NTerm |= NFactor
NTerm |= NTerm, NMulOp, NFactor, BinOpExpr

NMulOp |= '*', lambda: '*'
NMulOp |= '/', lambda: '/'
NMulOp |= KW_DIV, lambda: 'div'
NMulOp |= KW_MOD, lambda: 'mod'
NMulOp |= KW_AND, lambda: 'and'

NFactor |= NPower
NFactor |= NPower, '**', NFactor, lambda p, f: BinOpExpr(p, '**', f)

NPower |= KW_NOT, NPower, lambda p: UnOpExpr('not', p)
NPower |= VARNAME, VariableExpr
NPower |= NConst
NPower |= '(', NExpr, ')'

NConst |= INTEGER, lambda v: ConstExpr(v, Type.Integer)
NConst |= REAL, lambda v: ConstExpr(v, Type.Real)
NConst |= KW_TRUE, lambda: ConstExpr(True, Type.Boolean)
NConst |= KW_FALSE, lambda: ConstExpr(False, Type.Boolean)

Особенности:

  • Нечувствительность переменных к регистру обеспечивается приведением их имён к верхнему регистру (атрибут домена VARNAME вычисляется как str.upper).

  • Нечувствительность к регистру ключевых слов обеспечивается компиляцией их имени с флагом игнорирования регистра.

  • Там, где это возможно, в качестве семантического действия в правилах указывается просто имя конструктора класса соотвествующего узла. Например

    NTerm |= NTerm, NMulOp, NFactor, BinOpExpr

    вместо

    NTerm |= NTerm, NMulOp, NFactor, lambda t, op, f: BinOpExpr(t, op, f)

  • Имена нетерминалов начинаются на префикс N…, это позволяет избежать конфликтов с одноимёнными узлами синтаксического дерева.

Парсер, как обычно, пропускает пробельные символы и обычные комментарии Паскаля:

p.add_skipped_domain('(\\(\\*|\\{).*?(\\*\\)|\\})')

# Реализация

## Абстрактный синтаксис

```
Program -> Section*

Section -> TypeSection
         | ConstSection

TypeSection -> TypeDef+
ConstSection -> ConstDef+

TypeDef -> IDENT = TypeExpr
ConstDef -> IDENT = ConstExpr

TypeExpr -> NamedType
          | EnumType
          | RangeType
          | ArrayType
          | SetType
          | RecordType
          | PointerType

NamedType -> IDENT
           | INTEGER
           | REAL
           | CHAR
           | BOOLEAN

EnumType -> ( IDENT { , IDENT } )

RangeType -> ConstExpr .. ConstExpr

ArrayType -> array TypeExpr of TypeExpr

SetType -> set of TypeExpr

RecordType -> record RecordBody end

RecordBody -> ε
            | FieldList
            | VariantPart
            | FieldList ; VariantPart

FieldList -> Field { ; Field }

Field -> IdentList : TypeExpr

IdentList -> IDENT { , IDENT }

VariantPart -> case IDENT : NamedType of VariantBranchList

VariantBranchList -> VariantBranch { ; VariantBranch }

VariantBranch -> ConstList : ( FieldListOpt )

FieldListOpt -> ε
              | FieldList

ConstList -> ConstExpr { , ConstExpr }

PointerType -> ^ NamedType

ConstExpr -> INT_CONST
           | REAL_CONST
           | IDENT
           | + ConstExpr
           | - ConstExpr

CallbackType -> procedure ( FieldListOpt )
```

## Лексическая структура и конкретный синтаксис

### Лексическая структура

Ключевые слова:
TYPE, CONST, ARRAY, OF, SET, RECORD, END, CASE, INTEGER, REAL, CHAR, BOOLEAN, PROCEDURE.
Ключевые слова не чувствительны к регистру.

Идентификаторы:
IDENT -> [A-Za-z][A-Za-z0-9]*
Идентификаторы не чувствительны к регистру и при построении AST приводятся к верхнему регистру.

Целые константы:
INT_CONST -> [0-9]+

Вещественные константы:
REAL_CONST -> [0-9]+\.[0-9]+([eE][-+]?[0-9]+)?
            | [0-9]+[eE][-+]?[0-9]+

Игнорируются пробельные символы и комментарии вида { ... } и (* ... *).

### Конкретный синтаксис

```
Program -> Sections

Sections -> ε
         | Sections Section

Section -> TypeSection
         | ConstSection

TypeSection -> TYPE TypeDefs

ConstSection -> CONST ConstDefs

TypeDefs -> TypeDef
         | TypeDefs TypeDef

ConstDefs -> ConstDef
          | ConstDefs ConstDef

TypeDef -> IDENT = TypeExpr ;

ConstDef -> IDENT = ConstExpr ;

TypeExpr -> TypeName
          | ( IdentList )
          | ConstExpr .. ConstExpr
          | ARRAY TypeExpr OF TypeExpr
          | SET OF TypeExpr
          | ^ TypeName
          | RECORD END
          | RECORD FieldList END
          | RECORD FieldList ; END
          | RECORD VariantPart END
          | RECORD FieldList ; VariantPart END
          | PROCEDURE ( FieldListOpt )

TypeName -> IDENT
          | INTEGER
          | REAL
          | CHAR
          | BOOLEAN

FieldList -> Field
           | FieldList ; Field

Field -> IdentList : TypeExpr

VariantPart -> CASE IDENT : TypeName OF VariantList

VariantList -> VariantBranch
             | VariantList ; VariantBranch

VariantBranch -> ConstList : ( FieldListOpt )

FieldListOpt -> ε
              | FieldList

IdentList -> IDENT
           | IdentList , IDENT

ConstList -> ConstExpr
           | ConstList , ConstExpr

ConstExpr -> INT_CONST
           | REAL_CONST
           | IDENT
           | + ConstExpr
           | - ConstExpr
```

```python
from __future__ import annotations

import abc
import re
import sys
import os
from dataclasses import dataclass
from pprint import pformat

import parser_edsl as pe


# Абстрактное синтаксическое дерево


class Section(abc.ABC):
    pass


class TypeExpr(abc.ABC):
    pass


class ConstExpr(abc.ABC):
    pass


# Program -> Section*
@dataclass
class Program:
    sections: list[Section]


# Section -> TypeSection
@dataclass
class TypeSection(Section):
    definitions: list["TypeDef"]


# Section -> ConstSection
@dataclass
class ConstSection(Section):
    definitions: list["ConstDef"]


# TypeDef -> IDENT = TypeExpr
@dataclass
class TypeDef:
    name: str
    type_expr: TypeExpr


# ConstDef -> IDENT = ConstExpr
@dataclass
class ConstDef:
    name: str
    const_expr: ConstExpr


# TypeExpr -> NamedType
@dataclass
class NamedType(TypeExpr):
    name: str


# TypeExpr -> EnumType
# EnumType -> ( IDENT { , IDENT } )
@dataclass
class EnumType(TypeExpr):
    values: list[str]


# TypeExpr -> RangeType
# RangeType -> ConstExpr .. ConstExpr
@dataclass
class RangeType(TypeExpr):
    left: ConstExpr
    right: ConstExpr


# TypeExpr -> ArrayType
# ArrayType -> array TypeExpr of TypeExpr
@dataclass
class ArrayType(TypeExpr):
    index_type: TypeExpr
    element_type: TypeExpr


# TypeExpr -> SetType
# SetType -> set of TypeExpr
@dataclass
class SetType(TypeExpr):
    base_type: TypeExpr


# Field -> IdentList : TypeExpr
@dataclass
class Field:
    names: list[str]
    type_expr: TypeExpr


# VariantBranch -> ConstList : ( FieldListOpt )
@dataclass
class VariantBranch:
    labels: list[ConstExpr]
    fields: list[Field]


# VariantPart -> case IDENT : NamedType of VariantBranchList
@dataclass
class VariantPart:
    tag_name: str
    tag_type: NamedType
    branches: list[VariantBranch]


# TypeExpr -> RecordType
# RecordType -> record RecordBody end
@dataclass
class RecordType(TypeExpr):
    fields: list[Field]
    variant_part: VariantPart | None

# TypeExpr -> CallbackType
@dataclass
class CallbackType(TypeExpr):
    procedure_params: list[Field]

# TypeExpr -> PointerType
# PointerType -> ^ NamedType
@dataclass
class PointerType(TypeExpr):
    ref_type: NamedType


# ConstExpr -> INT_CONST
@dataclass
class IntConst(ConstExpr):
    value: int


# ConstExpr -> REAL_CONST
@dataclass
class RealConst(ConstExpr):
    value: float


# ConstExpr -> IDENT
@dataclass
class IdentConst(ConstExpr):
    name: str


# ConstExpr -> + ConstExpr
# ConstExpr -> - ConstExpr
@dataclass
class UnaryConst(ConstExpr):
    op: str
    expr: ConstExpr


# Лексическая структура

def normalize_ident(name: str) -> str:
    """Ключевые слова и идентификаторы нечувствительны к регистру.
    Для AST имена удобно хранить в верхнем регистре.
    """
    return name.upper()


# REAL_CONST -> вещественное число в десятичной записи
REAL_CONST = pe.Terminal(
    "REAL_CONST",
    r"(?:[0-9]+\.[0-9]+(?:[eE][-+]?[0-9]+)?|[0-9]+[eE][-+]?[0-9]+)",
    float,
    priority=6,
)

# INT_CONST -> [0-9]+
INT_CONST = pe.Terminal("INT_CONST", r"[0-9]+", int, priority=7)

# IDENT -> [A-Za-z][A-Za-z0-9]*
IDENT = pe.Terminal("IDENT", r"[A-Za-z][A-Za-z0-9]*", normalize_ident)


def make_keyword(image: str) -> pe.Terminal:
    return pe.Terminal(
        image,
        image,
        lambda _: None,
        re_flags=re.IGNORECASE,
        priority=10,
    )

NConstDefs |= NConstDefs, NConstDef, lambda constdefs, constdef: constdefs + [constdef]

NTypeExpr |= NConstExpr, "..", NConstExpr, RangeType

# Построение парсера

def build_parser() -> pe.Parser:
    parser = pe.Parser(NProgram, method=pe.EARLEY)

    # Пробелы, табы, переводы строк
    parser.add_skipped_domain(r"\s+")

    # Комментарии Pascal:
    # { ... }
    # (* ... *)
    parser.add_skipped_domain(r"(?:\{[\s\S]*?\}|\(\*[\s\S]*?\*\))")

    return parser


# Работа с файлами

def analyze_file(input_path: str, output_path: str) -> int:
    """Читает input-файл, строит AST и записывает результат в output-файл.
    Если output-файл уже существует, он перезаписывается.
    """
    parser = build_parser()

    try:
        with open(input_path, "r", encoding="utf-8") as f:
            source = f.read()

        tree = parser.parse(source)
        result_text = pformat(tree, sort_dicts=False, width=120)

        with open(output_path, "w", encoding="utf-8") as f:
            f.write(result_text)
            f.write("\n")
        print("Анализ завершён успешно. Результат записан в", output_path)
        return 0

    except pe.Error as e:
        error_text = f"Ошибка {e.pos}: {e.message}"
        with open(output_path, "w", encoding="utf-8") as f:
            f.write(error_text)
            f.write("\n")
        print(error_text, file=sys.stderr)
        return 1

    except Exception as e:
        error_text = f"Внутренняя ошибка: {e}"
        with open(output_path, "w", encoding="utf-8") as f:
            f.write(error_text)
            f.write("\n")
        print(error_text, file=sys.stderr)
        return 1


# Энтрипоинт

def main(argv: list[str]) -> int:
    if len(argv) <= 1:
        input_path = os.path.join(os.path.dirname(__file__), "assets/input.txt")
        output_path = os.path.join(os.path.dirname(__file__), "assets/output.txt")
    elif len(argv) == 2:
        input_path = argv[1]
        output_path = os.path.join(os.path.dirname(__file__), "assets/output.txt")
    else:
        input_path = argv[1]
        output_path = argv[2]

    return analyze_file(input_path, output_path)


if __name__ == "__main__":
    raise SystemExit(main(sys.argv))
```
