# Цель работы

Получение навыков выполнения семантического анализа.

# Индивидуальный вариант

Объявления типов и констант в Паскале.

Проверки:

- используемые идентификаторы должны быть определены выше по тексту;
- имена констант и типов находятся в общей области видимости и не
  должны повторяться;
- перечислимые типы также определяют константы;
- в записях не могут встречаться одноимённые поля.

Результат:

- программа выводит значения всех констант, включая пронумерованные с
  нуля элементы перечислений;
- для каждого типа вычисляется его объём;
- при ошибке выводятся её координата и описание.

# Реализация

Решение выполнено на основе синтаксического анализатора из лабораторной
работы 2.2. После построения AST запускается отдельная фаза
семантического анализа:

```python
tree = build_parser().parse(source.read())
tree.check()
print(tree.format_result())
```

Для хранения объявленных имён используется таблица символов:

```python
@dataclass
class SymbolTable:
    symbols: dict[str, Symbol] = field(default_factory=dict)

    def add(self, symbol: Symbol, pos: pe.Position) -> None:
        if symbol.name in self.symbols:
            raise RepeatedNameError(pos, symbol.name)
        self.symbols[symbol.name] = symbol

    def find(self, name: str, pos: pe.Position) -> Symbol:
        try:
            return self.symbols[name]
        except KeyError:
            raise UnknownNameError(pos, name)
```

Глобальная таблица содержит типы, константы и элементы перечислений.
Каждая запись содержит отдельную локальную таблицу полей.

Координаты потенциально ошибочных конструкций сохраняются в AST при
помощи расширенных действий `parser_edsl.ExAction`:

```python
@staticmethod
@pe.ExAction
def create(attrs, coords, res_coord):
    name, = attrs
    return NamedType(name, coords[0].start)
```

Размеры составных типов вычисляются рекурсивно. Размер массива равен
произведению количества индексов на размер элемента. Размер множества
равен числу байт, требуемых для битового представления его элементов.
Размер записи равен сумме размеров обычных полей и `case`-части. Размер
`case`-части равен размеру тега плюс размер наибольшей ветви.

Полный исходный код приведён в файле `main.py`. Подробное объяснение
реализации находится в `docs/implementation.md`.

# Тестирование

Автоматические тесты запускаются командой:

```sh
sh tests/run.sh
```

Они проверяют корректный пример, вычисление размеров составных типов,
общую область видимости типов и констант, порядок объявлений,
повторяющиеся поля записи и некорректные диапазоны.

## Пример входных данных

```pascal
const Limit = 3;
type
  Color = (red, green, blue);
  Values = array 1..Limit of Color;
  Flags = set of Color;
  Node = record value: Values; next: ^Node end;
```

## Вывод на `stdout`

```text
Программа корректна

Константы:
  LIMIT = 3
  RED = 0
  GREEN = 1
  BLUE = 2

Типы:
  COLOR = 2 байт
  VALUES = 6 байт
  FLAGS = 1 байт
  NODE = 10 байт
```

## Пример семантической ошибки

Входные данные:

```pascal
type
  Broken = Missing;
```

Вывод на `stderr`:

```text
Ошибка (2, 12): Имя MISSING не определено выше по тексту
```
