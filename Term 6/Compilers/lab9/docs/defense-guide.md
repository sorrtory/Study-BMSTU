# Гайд по защите лабораторной работы 3.3

## 1. Что открыть перед защитой

Откройте терминал в каталоге `lab9`:

```sh
cd lab9
```

Держите рядом четыре файла:

- `main.py` — реализация;
- `assets/input.txt` — полный корректный пример;
- `tests/unknown-name.pas` — пример ссылки на необъявленное имя;
- `docs/implementation.md` — подробное объяснение на случай уточнений.

Перед сдачей выполните:

```sh
sh tests/run.sh
```

Ожидаемый результат: семь тестов завершаются сообщением `OK`, после
чего запускается полный пример из `assets/input.txt`.

## 2. Короткое вступление

Можно начать так:

> Работа выполнена на основе лабораторной 2.2. Раньше парсер только
> строил абстрактное синтаксическое дерево для объявлений типов и
> констант Pascal. Теперь после синтаксического разбора запускается
> отдельный семантический обход AST. Он проверяет контекстные
> ограничения, накапливает таблицу символов, вычисляет значения
> констант и размеры типов.

Если преподаватель просит кратко перечислить проверки:

> Используемые идентификаторы должны быть объявлены выше по тексту.
> Типы, константы и элементы перечислений находятся в общем
> пространстве имён и не должны повторяться. Внутри каждой записи
> отдельно проверяются повторные поля.

## 3. Что показать в коде

Не нужно листать весь файл подряд. Достаточно пройти по пяти точкам.

### 3.1. Семантические ошибки

Покажите начало `main.py`: классы `SemanticError`,
`RepeatedNameError`, `RepeatedFieldError`, `UnknownNameError` и
`BadTypeError`.

Что сказать:

> Все семантические ошибки наследуются от `pe.Error`, поэтому
> обрабатываются так же единообразно, как ошибки парсера. В ошибке
> хранится координата и понятное сообщение. После первой ошибки обход
> прекращается.

### 3.2. Таблица символов

Покажите `Symbol`, `ConstSymbol`, `TypeSymbol`, `TypeInfo`,
`SymbolTable` и `SemanticContext`.

Что сказать:

> Символ — это имя вместе с информацией о сущности. Для константы
> сохраняется значение, для типа — размер и при необходимости
> мощность множества значений. Глобальная таблица одна, потому что по
> условию типы и константы имеют общее пространство имён.

Отдельно покажите `SymbolTable.add()` и `SymbolTable.find()`:

> `add()` обнаруживает повторное объявление, а `find()` — ссылку на
> необъявленное имя.

### 3.3. Семантический обход AST

Покажите `Program.check()`, `TypeDef.check()` и `ConstDef.check()`.

Что сказать:

> Обход идёт сверху вниз в порядке исходного текста. Правая часть
> объявления вычисляется до добавления имени в таблицу. Поэтому имя
> нельзя использовать раньше объявления.

Затем покажите `PointerType.evaluate()`:

> Для указателей оставлено одно исключение: `^List` может ссылаться на
> определяемый сейчас тип `List`. Размер указателя известен заранее и
> равен четырём байтам, поэтому рекурсивное определение списка
> корректно.

### 3.4. Координаты и `ExAction`

Покажите `NamedType.create()` или `IdentConst.create()`.

Что сказать:

> Обычное действие парсера получает только атрибуты, а расширенное
> действие `ExAction` также получает координаты символов правила.
> Позиция идентификатора сохраняется в узле AST и используется, если
> позднее семантическая проверка обнаруживает ошибку.

### 3.5. Вычисление размеров

Покажите методы `RangeType.evaluate()`, `ArrayType.evaluate()`,
`SetType.evaluate()`, `RecordType.evaluate()` и
`VariantPart.evaluate()`.

Что сказать:

> Размеры вычисляются рекурсивно. Массив занимает число элементов,
> умноженное на размер элемента. Множество хранится побитово.
> Обычная запись занимает сумму размеров полей. Вариантная часть
> записи занимает размер тега плюс максимальный размер одной ветви.

## 4. Что запустить

### 4.1. Полный корректный пример

```sh
python3 main.py assets/input.txt
```

В выводе обратите внимание на несколько строк:

```text
Программа корректна
...
RED = 0
GREEN = 1
BLUE = 2
...
GRAPHICSCREEN = 307200 байт
TOKEN = 42 байт
LIST = 46 байт
```

Что сказать:

> Элементы перечисления превращаются в константы со значениями от
> нуля. Размеры сложных типов вычисляются рекурсивно. В полном примере
> также есть вложенные записи, вариантная запись, множества, массивы и
> рекурсивный указатель.

### 4.2. Необъявленное имя

```sh
python3 main.py tests/unknown-name.pas
```

Ожидаемый результат:

```text
Ошибка (2, 12): Имя MISSING не определено выше по тексту
```

Что сказать:

> Файл синтаксически корректен, поэтому парсер строит AST. Ошибка
> появляется только на фазе семантического анализа. Координата взята
> из узла ссылки на тип.

### 4.3. Общее пространство имён

```sh
python3 main.py tests/duplicate-name.pas
```

Ожидаемый результат:

```text
Ошибка (4, 3): Повторное объявление имени ANSWER
```

Что сказать:

> Сначала объявлена константа `Answer`, затем тип с тем же именем.
> Это ошибка, потому что типы и константы находятся в общей таблице.

### 4.4. Повторное поле записи

```sh
python3 main.py tests/duplicate-field.pas
```

Ожидаемый результат:

```text
Ошибка (4, 5): Повторное поле X
```

Что сказать:

> Для каждого `record` создаётся отдельная локальная таблица полей.
> Глобальные имена и поля записи не смешиваются.

### 4.5. Дополнительная проверка диапазона

```sh
python3 main.py tests/inverted-range.pas
```

Ожидаемый результат:

```text
Ошибка (2, 14): Левая граница диапазона 10 больше правой 1
```

Что сказать:

> Эта проверка нужна для корректного вычисления мощности диапазона.
> Мощность затем используется при вычислении размера массива или
> множества.

## 5. Ожидаемые вопросы и ответы

### Что такое семантический анализ?

Это фаза компиляции после синтаксического анализа. Она проверяет
контекстные ограничения, которые неудобно или невозможно выразить
контекстно-свободной грамматикой: наличие объявления, видимость имени,
повторные объявления, согласованность типов и другие свойства.

### Чем семантическая ошибка отличается от синтаксической?

Синтаксическая ошибка означает, что текст нельзя построить по правилам
грамматики. Семантическая ошибка возникает у синтаксически допустимого
дерева. Например, `type A = Missing;` грамматически корректно, но имя
`Missing` не объявлено.

### Что такое AST?

AST — абстрактное синтаксическое дерево. Оно хранит существенные
конструкции программы без лишних деталей конкретной записи. Например,
узел массива хранит тип индекса и тип элемента, а не последовательность
всех токенов `array`, `of` и пробелов.

### Что добавилось в AST по сравнению с лабораторной 2.2?

Добавились координаты потенциально ошибочных конструкций, методы
`check()` и `evaluate()`, результаты вычисления размеров и таблицы
символов для областей, где они нужны.

### Что такое символ?

Символ — именованная сущность программы вместе с её описанием. В этой
работе глобальными символами являются типы и константы. У константы
хранится значение, у типа — `TypeInfo`.

### Что такое таблица символов?

Это отображение имени в соответствующий символ. В реализации она
построена на `dict`, то есть на хеш-таблице. Добавление проверяет
повторы, поиск обнаруживает неизвестные имена.

### Почему типы и константы лежат в одной таблице?

Это прямое требование индивидуального варианта: они находятся в общей
области видимости и не должны повторяться. Элементы enum также
добавляются в эту таблицу как константы.

### Почему идентификаторы переводятся в верхний регистр?

Pascal в этом варианте нечувствителен к регистру. Нормализация при
лексическом анализе позволяет считать `Color`, `COLOR` и `color` одним
именем и не усложнять сравнения далее.

### Почему проверка идёт в порядке исходного текста?

По условию использованное имя должно быть определено выше. Если
добавлять символ в таблицу только после вычисления правой части
объявления, ссылка вперёд естественным образом завершается ошибкой.

### Почему разрешена ссылка `^List` внутри объявления `List`?

Это рекурсивный тип через указатель. Его размер можно вычислить:
указатель всегда занимает четыре байта независимо от размера объекта.
Без такого исключения нельзя было бы объявить связный список из
примера задания.

### Почему нельзя аналогично разрешить `List = record next: List end`?

Это бесконечно рекурсивный тип без указателя. Для вычисления размера
`List` пришлось бы снова вычислять размер `List`, поэтому конечный
размер получить невозможно.

### Зачем в `TypeInfo` поле `cardinality`?

Это количество возможных значений конечного порядкового типа. Оно
нужно для массива и множества. Например, диапазон `1..10` имеет
мощность `10`, а перечисление `(red, green, blue)` — мощность `3`.

### Как считается размер массива?

Количество значений индексного типа умножается на размер элемента.
Например, `array 1..10 of INTEGER` занимает `10 * 2 = 20` байт.

### Как считается размер множества?

Каждому возможному элементу соответствует один бит. Поэтому размер
равен `ceil(cardinality / 8)` байт. Для трёх цветов нужен один байт.

### Как считается размер обычной записи?

Как сумма размеров полей. В учебной модели выравнивание и padding не
учитываются, потому что они не заданы условием.

### Как считается размер `case`-части записи?

Как размер поля тега плюс максимальный размер одной ветви. Одновременно
используется только одна ветвь, поэтому складывать размеры всех ветвей
не нужно.

### Почему `CHAR` и `BOOLEAN` занимают один байт?

Условие не задаёт их размеры явно. В реализации приняты стандартные
учебные значения по одному байту. Это допущение отражено в подробной
документации.

### Для чего используется алгоритм Эрли?

Он строит AST по грамматике лабораторной 2.2. Алгоритм Эрли подходит
для произвольных контекстно-свободных грамматик. Выбор алгоритма
синтаксического анализа не меняет логику отдельной семантической фазы.

### Что такое `ExAction`?

Это расширенное семантическое действие библиотеки `parser_edsl`.
Помимо атрибутов символов правила оно получает их координаты. Благодаря
этому координата сохраняется в AST и затем попадает в сообщение об
ошибке.

### Почему анализатор сообщает только одну ошибку?

Так сформулировано задание: для некорректной программы требуется
вывести координату и описание первой семантической ошибки. После
исключения дальнейший обход прекращается.

### Получен ли дополнительный балл за локальные таблицы?

В решении используются локальные таблицы полей для `RecordType`.
Это полезная часть подхода из лекции.
Полный граф локальных таблиц со ссылками на открытые области и
рекурсивным поиском не реализован, потому что для обязательных
конструкций варианта он не требуется. Не стоит заявлять полноценную
реализацию бонуса без отдельного согласования с преподавателем.

### Что потребовалось бы добавить для полноценного бонусного варианта?

Нужно добавить в `SymbolTable` ссылки на таблицы открытых областей,
реализовать рекурсивный поиск эффективного символа и явно подвесить
локальные таблицы ко всем узлам AST, соответствующим областям
видимости.

## 6. Быстрый сценарий защиты

Если времени мало, достаточно такого порядка:

1. Сказать вступление из раздела 2.
2. Показать `Program.check()`, `SymbolTable` и один `ExAction`.
3. Запустить `sh tests/run.sh`.
4. Запустить `python3 main.py tests/unknown-name.pas`.
5. Объяснить формулу размера массива, множества и `case`-части.

Это покрывает назначение работы, обязательные проверки, координаты
ошибок и вычисление результатов.
