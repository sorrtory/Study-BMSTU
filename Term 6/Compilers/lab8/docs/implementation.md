# Как устроен форматтер

## 1. Постановка задачи

Лабораторная работа посвящена генератору синтаксических анализаторов
`bison`. Требуется разработать сильный форматтер для учебного диалекта
Бейсика.

Форматтер получает исходный текст программы, проверяет его
синтаксическую структуру и выводит тот же текст в едином стиле. Сильный
форматтер может не только добавлять пробелы, но и менять расположение
строк. В этой реализации комментарии удаляются, а строки, перенесённые
при помощи `_`, склеиваются.

Например, вход:

```basic
Function Sum#(a#,b#)
Sum#=a#+b#
End Function
```

Выход:

```basic
Function Sum#(a#, b#)
  Sum# = a# + b#
End Function
```

## 2. Конвейер обработки

Программа состоит из четырёх частей:

```text
исходный текст
    ↓
лексический анализатор Flex
    ↓ поток токенов
синтаксический анализатор Bison
    ↓ семантические действия
модуль форматирования
    ↓
отформатированный текст
```

Точка входа находится в `src/main.c`. Она открывает файл или использует
`stdin`, создаёт scanner, инициализирует форматтер и вызывает
`yyparse(scanner, &formatter)`.

## 3. Лексический анализатор

Лексический анализатор описан в `src/lexer.l`.

Опции:

```text
reentrant       scanner хранит состояние в отдельном объекте
bison-bridge    scanner передаёт Bison семантические значения токенов
bison-locations scanner передаёт позиции токенов
caseless        ключевые слова не зависят от регистра
```

Это соответствует условию задания: анализатор должен быть
реентрантным, а ключевые слова Бейсика не чувствительны к регистру.

Lexer распознаёт:

- ключевые слова: `Function`, `Sub`, `If`, `Then`, `Else`, `For`,
  `To`, `Next`, `Do`, `While`, `Until`, `Loop`, `Dim`, `End`;
- операции и разделители;
- числа и строки;
- типизированные идентификаторы переменных и функций, например `i%`,
  `SumArray#`, `Join$`;
- имена процедур без суффикса типа, например `Fibonacci`;
- значимые переводы строк.

Комментарии начинаются с `'` и отбрасываются lexer:

```lex
"'"[^\n]* ;
```

Перенос строки при помощи `_` также отбрасывается вместе с последующим
переводом строки:

```lex
_[ \t]*("'"[^\n]*)?\n ;
```

Обычный перевод строки превращается в токен `NEWLINE`. Это важно:
в данном диалекте Бейсика граница строки разделяет операторы.

Структура `Extra` из `src/lexer.h` хранит текущие строку и столбец.
Макрос `YY_USER_ACTION` обновляет координаты после каждого токена.
Благодаря этому сообщение об ошибке содержит позицию.

## 4. Синтаксический анализатор

Грамматика находится в `src/parser.y`.

Реентрантность включается директивой:

```bison
%define api.pure full
```

Scanner и объект форматтера явно передаются в parser:

```bison
%lex-param   {yyscan_t scanner}
%parse-param {yyscan_t scanner}
%parse-param {struct Formatter *formatter}
```

Глобальное изменяемое состояние не используется.

### Верхний уровень

Программа состоит из функций и процедур:

```text
program → modules
module  → function | sub
```

Для функции и процедуры parser печатает заголовок, увеличивает отступ,
разбирает тело и затем печатает завершающую строку.

### Операторы

Нетерминал `statement` объединяет поддержанные операторы:

```text
assignment | dim_stmt | call_stmt | if_stmt | for_stmt | do_stmt
```

Вложенные конструкции разбираются рекурсивно. Поэтому один механизм
отступов работает для произвольной глубины вложенности.

### Выражения

Приоритеты операций задаются директивами Bison:

```bison
%left '=' '<' '>' GE LE NE
%left '+' '-'
%left '*' '/'
%precedence UMINUS
```

Например, `a# + b# * c#` разбирается как сумма, у которой справа
находится произведение. После разбора семантические действия
восстанавливают выражение с единообразными пробелами.

И вызов функции, и индексация массива через круглые скобки представлены
одним нетерминалом `variable`. Это соответствует условию: синтаксически
отличить их невозможно. Квадратная индексация не поддерживается.

### Циклы Do Loop

Грамматика поддерживает все формы из варианта:

```basic
Do While condition
Loop

Do Until condition
Loop

Do
Loop While condition

Do
Loop Until condition

Do
Loop
```

Общий префикс вынесен в `do_body`, а необязательный хвост — в
`do_tail`. Это устраняет неоднозначность грамматики.

## 5. Семантические действия

Семантические действия встроены в `src/parser.y`. Для простых
выражений они формируют строки:

```c
$$ = text_join($1, " + ", $3);
```

Для операторов готовая строка передаётся модулю форматирования:

```c
formatter_line(formatter, $1);
```

Для блочных конструкций используются функции:

- `formatter_begin_module` — начало функции или процедуры;
- `formatter_begin_block` — начало вложенного блока;
- `formatter_else` — переход к ветви `Else`;
- `formatter_end_block` — закрытие блока;
- `formatter_line` — обычная строка.

Реализация этих функций находится в `src/formatter.c`. Текущий уровень
отступа хранится в `struct Formatter`.

Строки выражений размещаются динамически. После использования память
освобождается. Директива `%destructor` освобождает значения токенов,
которые остаются в стеке parser при синтаксической ошибке.

## 6. Обработка ошибок

Lexer возвращает токен `INVALID` для неизвестного символа. Parser
останавливается при первой ошибке и вызывает `yyerror`.

Пример:

```text
Syntax error at 2:16: syntax error, unexpected NEWLINE
```

Программа возвращает код завершения `1`. Отформатированный префикс до
ошибки может быть уже выведен: parser работает потоково и обязан
остановиться после обнаружения первой ошибки.

## 7. Сборка

Команда:

```sh
make
```

выполняет три шага:

```text
bison → src/parser.tab.c, src/parser.tab.h
flex  → src/lex.yy.c
gcc   → basic-formatter
```

Генерируемые файлы и исполняемый файл не входят в исходники проекта и
удаляются командой:

```sh
make clean
```

## 8. Тестирование

Команда:

```sh
make test
```

запускает `tests/run.sh`.

Позитивные тесты форматируются и сравниваются с ожидаемыми файлами при
помощи `diff`. Фактический вывод остаётся в файлах `tests/*.actual`,
чтобы его можно было открыть и показать отдельно.

Ошибочный пример вынесен в отдельную цель:

```sh
make test2
```

Она запускает `tests/run-invalid.sh`. Для этого теста нет expected-файлов
и нет `diff`: formatter должен напечатать сообщение об ошибке и
завершиться с ненулевым кодом. Скрипт считает это успешным результатом.

Файл `tests/example.bas` покрывает основные конструкции варианта:
функции, процедуру, массивы, `Dim`, `If`, `Else`, `For`, `Do While`,
комментарии и перенос `_`.

Файл `tests/do-loops.bas` отдельно проверяет остальные формы
`Do ... Loop`.
