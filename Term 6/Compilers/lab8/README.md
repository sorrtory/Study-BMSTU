# Лабораторная работа 3.2: форматтер исходных текстов

Проект выполнен в рамках лабораторной работы по генератору
синтаксических анализаторов `bison`. Задача состоит не просто в проверке
корректности программы, а в преобразовании исходного текста учебного
диалекта Бейсика в единообразно оформленный текст.

На вход можно подать программу с неаккуратными пробелами, комментариями
и переносами длинных строк. На выходе получится программа с
нормализованными пробелами, переводами строк и отступами. Такой
инструмент называется сильным форматтером: он имеет право менять
расположение строк, сохраняя структуру исходной программы.

Для решения используются два генератора:

- `flex` создаёт реентрантный лексический анализатор;
- `bison` создаёт реентрантный синтаксический анализатор.

Грамматика языка описана в `src/parser.y`. В неё встроены семантические
действия, которые по мере разбора печатают отформатированный текст.

Форматтер:

- удаляет комментарии, начинающиеся с апострофа;
- склеивает строки, перенесённые при помощи `_`;
- нормализует пробелы в выражениях и списках аргументов;
- расставляет переводы строк и двухпробельные отступы;
- завершает работу при первой синтаксической ошибке.

Поддерживаются функции, процедуры, `Dim`, присваивания, условия
`If ... Then ... Else ... End If`, циклы `For ... Next`, пять форм
`Do ... Loop`, выражения, вызовы функций и обращения к массивам.

## Структура проекта

```text
.
├── src/                  исходники форматтера
├── tests/                входные данные и ожидаемый вывод
├── docs/                 подробная документация
├── parser_bison-2026/    исходный учебный пример
├── Makefile              команды сборки и тестирования
└── README.md             краткая справка
```

Основные исходники:

- `src/lexer.l` — правила лексического анализа;
- `src/parser.y` — грамматика и семантические действия;
- `src/formatter.c` — вывод строк с нужным уровнем отступа;
- `src/main.c` — запуск scanner и parser;
- `tests/` — позитивные и негативные примеры.

## Сборка

Требуются `flex`, `bison`, `gcc` и `make`.

```sh
make
```

## Использование

Входной файл можно передать первым аргументом:

```sh
./basic-formatter tests/example.bas
```

Без аргумента программа читает исходный текст из `stdin`:

```sh
./basic-formatter < tests/example.bas
```

Отформатированный текст выводится в `stdout`, сообщения об ошибках —
в `stderr`.

## Тестирование

```sh
make test
```

Эта команда проверяет корректные примеры и оставляет файлы
`tests/*.actual`, чтобы можно было посмотреть фактический вывод.

Отдельный ошибочный пример запускается так:

```sh
make test2
```

Он печатает сообщение синтаксической ошибки для `tests/invalid.bas` и
считается успешным, если formatter действительно завершился с ошибкой.
