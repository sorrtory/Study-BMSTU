# AGENTS.md

## Описание проекта

Это курсовая работа по курсу "Базы данных".

### Тема проекта

Сравнительный анализ нормализованной и документно-ориентированной моделей
хранения данных системы видеонаблюдения

### Задание

- Провести сравнительный анализ моделей хранения данных СУБД PostgreSQL и MongoDB
  на примере задачи системы видеонаблюдения.
- Проектирование проводить с учетом цели хранения - обеспечение возможности
  анализа ситуаций по данным большого количества видеокамер.
- В качестве показателей при сравнении фиксировать время записи и чтения
  при различной нагрузке системы

## Структура репозитория

В этой главе идет описание структуры репозитория и указание на файлы, которые относятся к курсовой работе. Это поможет ориентироваться в проекте и понимать, какие файлы стоит использовать, а какие игнорировать.

### Отчет по курсовой работе

При задачах, связанных с написанием отчета, важно придерживаться одного заданного шаблона и стиля. При добавлении новых файлов, требуется обновлять файловой описание в соответствующем разделе.

### Редактирование русского текста отчёта

Для правки русскоязычных LaTeX-файлов отчёта в `report/Content/*.tex` используй skill `humanizer-ru`.

Цель правки:

- улучшить естественность русского текста, ясность и академический стиль;
- сохранить факты, технический смысл, структуру, LaTeX-команды, `\label`, `\ref`, `\cite`, формулы, таблицы, листинги и имена файлов;
- не добавлять новые утверждения, источники, результаты измерений или выводы без явной просьбы;
- убирать канцелярит, кальки с английского, воду, перегруженные родительные цепочки, однообразный синтаксис и неестественный AI-ритм;
- сохранять формальный стиль технического отчёта, не делать текст разговорным или рекламным;
- предпочитать небольшие diff-правки вместо полного переписывания раздела, если это возможно или нет четкого запроса на структурные изменения.

### Код курсовой работы

- `src/docs/` - папка с документацией по курсовой работе
- `src/apps/client/` - папка с кодом фронтенда на Vue
- `src/apps/server/` - папка с кодом бэкенда на Express
- `src/apps/loadgen/` - папка с кодом воркера на Go, он общается с базой данных и создает нагрузку
- `src/grafana/` - папка с настройками дашборда Grafana для мониторинга баз данных

#### Документация

- `src/docs/architecture.md` - описание архитектуры программной системы
- `src/docs/system-scenario.md` - описание сценария использования системы видеонаблюдения
- `src/docs/load-scenario.md` - описание сценария запросов к системе видеонаблюдения
- `src/docs/load-metrics.md` - описание метрик, которые будут использоваться для сравнения моделей данных.
- `src/docs/log.md` - журнал изменений. При добавлении новых библиотек и прочих важных команд, которые захочиться повторить, требуется добавить запись в этот файл.

#### Модели данных

- `src/docs/er.md` - ER-диаграмма предметной области. Может иметь many-to-many связи. Ее не нужно нормализовать, она просто описывает предметную область и ее сущности. Концептульная модель. Замечание: для mermaid необходимо использовать симовол `ㅤ` чтобы сделать пустое поле в диаграмме, иначе mermaid будет ругаться на отсутствие атрибутов у сущности.

- `src/docs/rel_jsonb.md` - реляционная модель для PostgreSQL с использованием JSONB. Частично нормализованная модель, которая использует JSONB для хранения вложенных данных.
- `src/docs/rel_norm.md` - полностью нормализованная реляционная модель для PostgreSQL. Все сущности и связи представлены в виде отдельных таблиц.
- `src/docs/doc_nested.md` - вложенная документная модель для MongoDB. Все данные хранятся в виде документов, которые могут содержать вложенные документы и массивы.
- `src/docs/doc_norm.md` - нормализованная документная модель для MongoDB. Данные хранятся в виде документов, но при этом используются ссылки $ref между документами для представления связей между сущностями.

Важно: описание моделей данных должно строго совпадать с реализацией в коде и текстовым описанием в отчете. Если найдено несоответствие, необходимо уведомить об этом пользователя агента и указать на конкретные места в коде или отчете, где обнаружено несоответствие. Первостепенный источник истины - `src/docs/` - эти модели данных должны быть актуальными.

## Технические требования

### Node.js

В моей системе установлен `fnm`. В этом проекте используется `pnpm` для управления зависимостями. Если он не доступен, необходимо загрузить `fnm`:

```bash
FNM_PATH="~/.local/share/fnm"
if [ -d "$FNM_PATH" ]; then
   export PATH="$FNM_PATH:$PATH"
   eval "$(fnm env --shell zsh)"
fi
```

После чего `pnpm` будет доступен!

### Окружение .env

Файл `src/.env` содержит переменные окружения для конфигурации приложения.
Он должен соответсвовать шаблону `.env.example`.
То есть добавляя новые переменные окружения:

1. Добавляй их в `.env.example` и документируй, что это за переменная и для чего она нужна
2. Добавляй их в `.env` и заполняй значениями для локальной разработки

## Описание компонентов программной системы

### Клиент

- Клиент - это веб-приложение на `Vue 3`, которое позволяет пользователю выбирать сценарий нагрузки и отображает результаты в виде графиков, используя встроенные дашборды Grafana.
- Используй `pnpm` для управления зависимостями. Не забыывая обновлять `docs/log.md` при добавлении новых зависимостей.
- Используй Composition API и `<script setup lang="ts">`
- Основное правило - не усложнять. Не нужно создавать сложные компоненты и архитектуру, если можно обойтись простыми решениями. Цель - продемонстрировать работу с базой данных и визуализацию результатов, а не создавать сложное приложение.

### Express сервер

- Сервер - это бэкенд на `Express`, который обрабатывает запросы от клиента, перенаправляет их к loadgen

### Loadgen

- Loadgen - это воркер на `Go`, который общается с базой данных и создает нагрузку. Он реализует сценарии нагрузки. Одновременно запущенно два экземпляра loadgen - один для PostgreSQL, другой для MongoDB. Они работают независимо и создают нагрузку на свои базы данных. Они делят одну кодовую базу, но при этом используют разные конфигурационные файлы для подключения к разным базам данных.

Важно: При работе с базой данных запрещено использовать ORM. Все запросы должны быть написаны вручную!
