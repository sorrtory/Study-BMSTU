В JSONB-модели все особенности события можно положить в одно поле event.payload. Например, для события обнаружения объекта там лежит массив объектов, confidence, координаты, параметры кадра.


Если нужно объяснять подробнее:

Первая нормальная форма, 1NF
Значения в таблице должны быть атомарными: в одной ячейке не должно быть массива или сложного объекта.
В проекте это означает: нельзя просто хранить список обнаруженных объектов внутри одной ячейки, если мы хотим строгую реляционную модель. Нужно вынести объекты в отдельную таблицу.

Вторая нормальная форма, 2NF
Неключевые поля должны зависеть от всего ключа, а не от его части.
Это важно для таблиц со составными ключами, например таблиц связей. Если есть event_id и camera_id, то данные, относящиеся только к камере, не должны лежать в этой таблице связи.

Третья нормальная форма, 3NF
Неключевые поля не должны зависеть друг от друга через промежуточные поля.
Например, если у события есть event_type, то описание типа события не надо дублировать в каждой строке события. Оно выносится в справочник event_type.

BCNF, нормальная форма Бойса-Кодда
Более строгий вариант 3NF: любая функциональная зависимость должна определяться ключом.
Проще сказать: если поле определяет другое поле, оно само должно быть ключом или частью ключевой сущности. Это помогает убрать скрытые зависимости и дублирование.



В PostgreSQL JSONB событие может выглядеть концептуально так:

```json
{
  "event_type": "object_detected",
  "severity": "high",
  "payload": {
    "frame_time_ms": 1240,
    "objects": [
      {
        "object_type": "person",
        "confidence": 0.94,
        "bbox": { "x": 120, "y": 80, "w": 40, "h": 100 }
      }
    ]
  }
}
```
В JSONB-модели это в основном одна строка в event, плюс связь с камерой через event_camera.

А в нормализованной модели это раскладывается примерно так:

event — базовый факт события: время, зона, confidence;
event_type — справочник типов событий;
event_severity — справочник уровней значимости;
event_camera — связь события и камер;
object_detection_event_detail — детали события обнаружения объектов;
detected_object — каждый найденный объект отдельной строкой;
object_type — справочник типов объектов;
при другом типе события будут другие таблицы деталей: motion_event_detail, line_crossing_event_detail, signal_lost_event_detail.
